# ONE — Authentication Setup

## Native email confirmation

ONE uses Supabase Auth with PKCE for mobile email confirmation and password recovery.

Current native callbacks:

- `one://auth/callback`
- `one://auth/reset-password`

App-side implementation:

- Expo scheme: `one`
- Supabase client flow: `pkce`
- sign-up `emailRedirectTo`: `one://auth/callback`
- password reset `redirectTo`: `one://auth/reset-password`
- confirmation route: `app/auth/callback.tsx`
- password reset route: `app/auth/reset-password.tsx`
- both flows exchange the authorization code with `exchangeCodeForSession`

## Required Supabase dashboard configuration

In the dedicated ONE Supabase project, open:

Auth → URL Configuration

Add these exact values to Additional Redirect URLs:

- `one://auth/callback`
- `one://auth/reset-password`

The redirect URL supplied by the app must be present in Supabase's allowed Redirect URLs list.

## Email template check

If an email template has been customized, verify that it preserves the redirect target generated by Supabase. A customized template that always hard-codes the Site URL can ignore the redirect supplied by the app.

## Native beta verification — account confirmation

1. Install the ONE development build on the iPhone.
2. Create a new account in Settings.
3. Open the Supabase confirmation email on the same device.
4. Tap the confirmation link.
5. Confirm that iOS opens ONE.
6. Confirm that `app/auth/callback.tsx` exchanges the PKCE code.
7. Confirm that Settings shows the authenticated account.
8. Restart ONE and confirm the session persists.

## Native beta verification — password recovery

1. Sign out of ONE.
2. Enter the account email in Settings.
3. Tap `Forgot password?`.
4. Open the password reset email on the same device.
5. Confirm that iOS opens `one://auth/reset-password` in ONE.
6. Enter and confirm a new password of at least 8 characters.
7. Confirm that the password update succeeds.
8. Sign out and sign back in with the new password.
9. Confirm that the old password no longer works.

## Public-launch hardening

For the first native beta, the custom `one://` scheme is sufficient.

Before broad public launch, evaluate an HTTPS web callback / Universal Link flow. This is more robust across email clients and link scanners and avoids relying solely on a custom URL scheme.
