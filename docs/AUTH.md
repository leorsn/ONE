# ONE — Authentication Setup

## Native email confirmation

ONE uses Supabase Auth with PKCE for mobile email confirmation.

Current native callback:

`one://auth/callback`

App-side implementation:

- Expo scheme: `one`
- Supabase client flow: `pkce`
- sign-up `emailRedirectTo`: `one://auth/callback`
- callback route: `app/auth/callback.tsx`
- callback exchanges the authorization code with `exchangeCodeForSession`

## Required Supabase dashboard configuration

In the dedicated ONE Supabase project, open:

Auth → URL Configuration

Add this exact value to Additional Redirect URLs:

`one://auth/callback`

The redirect URL supplied by the app must be present in Supabase's allowed Redirect URLs list.

## Email template check

If the confirmation email template has been customized, verify that it preserves the redirect target generated by Supabase. A customized template that always hard-codes the Site URL can ignore `emailRedirectTo`.

## Native beta verification

1. Install the ONE development build on the iPhone.
2. Create a new account in Settings.
3. Open the Supabase confirmation email on the same device.
4. Tap the confirmation link.
5. Confirm that iOS opens ONE.
6. Confirm that `app/auth/callback.tsx` exchanges the PKCE code.
7. Confirm that Settings shows the authenticated account.
8. Restart ONE and confirm the session persists.

## Public-launch hardening

For the first native beta, the custom `one://` scheme is sufficient.

Before broad public launch, evaluate an HTTPS web callback / Universal Link flow. This is more robust across email clients and link scanners and avoids relying solely on a custom URL scheme.
