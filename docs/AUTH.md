# NEVER — Authentication Setup

## Native email confirmation

NEVER uses Supabase Auth with PKCE for mobile email confirmation and password recovery.

Final native callbacks:

- `never://auth/callback`
- `never://auth/reset-password`

App-side implementation:

- Expo scheme: `never`
- Supabase client flow: `pkce`
- sign-up `emailRedirectTo`: `never://auth/callback`
- password reset `redirectTo`: `never://auth/reset-password`
- confirmation route: `app/auth/callback.tsx`
- password reset route: `app/auth/reset-password.tsx`
- both flows exchange the authorization code with `exchangeCodeForSession`

## Required Supabase dashboard configuration

In the dedicated NEVER Supabase project, open:

Auth → URL Configuration

Add these exact values to Additional Redirect URLs:

- `never://auth/callback`
- `never://auth/reset-password`

The redirect URL supplied by the app must be present in Supabase's allowed Redirect URLs list.

Do not retain the old `one://` callbacks for the public launch candidate unless a deliberate migration bridge is introduced later. The app no longer accepts the legacy scheme.

## Email template check

If an email template has been customized, verify that it preserves the redirect target generated by Supabase. A customized template that always hard-codes the Site URL can ignore the redirect supplied by the app.

All consumer-facing sender names, subjects and body copy must use NEVER branding.

## Native verification — account confirmation

1. Install the current NEVER build on the iPhone.
2. Create a new account.
3. Open the Supabase confirmation email on the same device.
4. Tap the confirmation link.
5. Confirm that iOS opens NEVER through `never://auth/callback`.
6. Confirm that `app/auth/callback.tsx` exchanges the PKCE code.
7. Confirm that Settings shows the authenticated account.
8. Restart NEVER and confirm the session persists.

## Native verification — password recovery

1. Sign out of NEVER.
2. Enter the account email on the sign-in screen.
3. Tap `Forgot password?`.
4. Open the password reset email on the same device.
5. Confirm that iOS opens `never://auth/reset-password` in NEVER.
6. Enter and confirm a new password of at least 8 characters.
7. Confirm that the password update succeeds.
8. Sign out and sign back in with the new password.
9. Confirm that the old password no longer works.

## Public-launch hardening

The first public NEVER release uses the `never://` custom scheme. Before broader expansion, an HTTPS Universal Link callback can still be evaluated as an additional hardening layer for email-client/link-scanner interoperability, but it is not required to preserve the retired ONE namespace.
